# AUB — Обзор проекта

## Что такое AUB?

**AUB** — полноценная электронная система управления и учёта для академии. Это не только мобильное приложение. Цель — автоматизировать процессы управления академией: учёт студентов, рабочие процессы персонала, расписание, посещаемость, платежи, документы и отчётность.

## Бизнес-цель

Создать централизованную цифровую платформу для академии, которая:

- заменяет разрозненные таблицы и ручные процессы;
- предоставляет администраторам полноценную CRM/админ-панель;
- предоставляет персоналу рабочие места с ограниченным доступом в зависимости от роли;
- в будущем обеспечивает мобильный доступ для студентов, родителей и преподавателей.

## Основная концепция системы

Система имеет **центральное ядро CRM/админки** и несколько будущих каналов доступа:

| Канал | Аудитория | Статус |
|-------|-----------|--------|
| Полная админ-панель | Администраторы | Установлено + модули AUB в разработке |
| Рабочие места по ролям | Секретариат, преподаватели, другой персонал | **Реализовано** (Фаза 1, 2026-07-06) |
| Мобильное приложение — студенты | Студенты | Будущее |
| Мобильное приложение — родители | Родители/опекуны | Будущее |
| Мобильное приложение — преподаватели | Преподаватели | Будущее |

## Текущее установленное состояние

Проект в `/var/www/aub` был установлен заново **2026-07-06** с:

- **Laravel** 13.18.1
- **`owlsolutions/custom-admin-kit`** v0.4.0 (пресет admin)
- **Inertia.js + React + Vite + Tailwind + Ziggy**
- База данных **MySQL** `aub`

Страница входа обслуживается по адресу **`/`** (корень). Устаревший `/login` перенаправляет на `/`.

Тестовый администратор существует: `admin@admin.com` (создан через `owl-admin:make-admin`).

## Универсальный kit vs модули AUB

| Generic kit | Реализация AUB | Статус |
|-----------|----------------|--------|
| `customers` | **Students** — расширенный профиль на `customers` | Частично (2026-07-06+) |
| `services` | **Courses** — отдельная таблица `courses` | Реализовано |
| `staff` (справочник) | **Teachers** + **Staff Roles** | Teachers готово; RBAC готово |
| `orders` | **Enrollments** — pivot `course_group_customer` | Частично |
| `calendar` | **Weekly schedule** на `/schedule-service` | Реализовано |
| User management в `/settings` | **Role-based access control** | Реализовано |

**Важно:** модуль `staff` в kit — это универсальный CRM-справочник персонала. Это **не** запланированная система Staff Roles & Role-Based Workplaces. Колонка `staff.role` в kit — текстовое поле, а не RBAC.

## Полная админ-панель vs рабочие места по ролям

- **Полная админ-панель** — все пункты меню, все CRM-модули, настройки, управление пользователями. Предназначена только для пользователей с ролью **Administrator**.
- **Рабочее место по ролям** — ограниченный набор экранов для неадминистративного персонала. **Реализовано** — см. [USER_ROLES_AND_ACCESS.md](USER_ROLES_AND_ACCESS.md).

## Краткое описание объёма MVP

**Завершено или в процессе:**

1. Staff Roles & Role-Based Workplaces ✅ (Фаза 1, 2026-07-06)
2. Основные записи: студенты (частично), преподаватели, курсы, группы, уроки, зачисления (частично)
3. Операции: недельное расписание + гибридный ИИ ✅; посещаемость, отдельные документы — в ожидании
4. Основы учёта: не начато
5. Админ-пользователи и права (через роли) ✅

**Явно не входит в MVP Phase 1 core:**

- Управление костюмами (`servizio costumi`)
- Участие в шоу/мероприятиях (`servizio spettacoli`)
- Билеты, аренда костюмов, взносы за участие
- Мобильные приложения (запланированы на более поздние фазы)
