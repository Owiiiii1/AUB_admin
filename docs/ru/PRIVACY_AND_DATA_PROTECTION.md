# AUB — Конфиденциальность и защита данных

> Это техническая/проектная документация, **а не окончательный юридический текст**. Перед использованием в production и публикацией в App Store требуется юридическая экспертиза квалифицированного специалиста.

## Обзор

AUB — система управления академией, которая будет обрабатывать **персональные данные** и **данные детей**. Конфиденциальность и защита данных должны быть заложены в систему с самого начала, а не добавлены позже.

## Role-based access как требование конфиденциальности

Планируемая система **Staff Roles & Role-Based Workplaces** — это **требование конфиденциальности**, а не только удобство.

- Сотрудники должны иметь доступ только к данным, необходимым для их работы
- Учителя не должны видеть платёжные данные или контакты родителей, если это явно не разрешено
- Медицинские и чувствительные заметки требуют максимального ограничения доступа
- Доступ родителей и студентов (будущие мобильные каналы) должен быть ограничен только их собственными данными

Без контроля доступа на основе ролей система не может соответствовать принципам минимизации данных.

## Роли контролёра и обработчика данных

| Роль | Субъект | Ответственность |
|------|--------|----------------|
| **Data Controller** (Titolare del trattamento) | Академия (AUB) | Определяет цели и средства обработки |
| **Data Processor** (Responsabile del trattamento) | OwlSolutions / разработчик | Обрабатывает данные от имени контролёра при доступе к серверу, базе данных, резервным копиям, панели администратора или инструментам поддержки |

**Рекомендация:** По возможности регистрировать сервер и базу данных под владением академии. Между академией и любым техническим провайдером с доступом к системе следует подписать соглашения об обработке данных (DPA).

## Типы обрабатываемых данных

| Категория данных | Примеры | Чувствительность |
|---------------|----------|-------------|
| Staff personal data | Имена, email, телефоны сотрудников | Personal data |
| Student personal data | Имена, даты рождения, адреса | **Children's data** |
| Parent/guardian data | Имена, email, телефоны, адреса | Personal data |
| Financial data | Payments, invoices, debts | Personal + financial |
| Health/sensitive notes | Медицинская информация, особые потребности | **Special category** (if stored) |
| Consent records | Согласие на фото, согласие на обработку данных | Children's data |
| System logs | IP addresses, login times | Personal data (limited) |
| AI provider keys | API keys в `ai_provider_settings` | Technical secrets |

## Данные детей — особая осторожность

Академия обслуживает несовершеннолетних. Применяется усиленная защита:

- Собирать только необходимые поля данных
- Ограничивать доступ по ролям (см. [USER_ROLES_AND_ACCESS.md](USER_ROLES_AND_ACCESS.md))
- Не показывать данные детей неавторизованным ролям
- Планировать audit logging доступа к записям студентов

### Италия — согласие для несовершеннолетних в интернете

Согласно итальянскому законодательству (D.Lgs. 196/2003 с изменениями, GDPR и связанным руководством):

- Для детей **младше 14 лет** онлайн-согласие на обработку данных, как правило, требует разрешения родителя или законного опекуна
- Академия должна получить и зафиксировать действительное согласие перед обработкой данных детей через цифровые каналы (web, mobile apps)
- Записи согласия должны храниться со ссылкой на версию действующей политики конфиденциальности

**Планируемая сущность:** `ConsentRecord`, связанная с `PrivacyPolicyVersion` — см. [DATA_MODEL_DRAFT.md](DATA_MODEL_DRAFT.md).

## Принципы GDPR, применённые к AUB

| Принцип | Реализация в AUB |
|-----------|---------------------|
| Lawfulness, fairness, transparency | Privacy policy, consent records |
| Purpose limitation | Module-based data collection; no scope creep |
| Data minimization | Role-based field visibility; minimal required fields |
| Accuracy | Edit workflows with audit trail (planned) |
| Storage limitation | Retention policies (to be defined with academy) |
| Integrity and confidentiality | Auth, RBAC, encrypted connections (HTTPS), hashed passwords |
| Accountability | Documentation, consent records, access logs (planned) |

## Технические меры безопасности (текущие и планируемые)

### Текущие (реализованы)

- HTTPS через Nginx (`https://aub.owlsolutions.net`)
- Session-based authentication
- Password hashing (bcrypt)
- CSRF protection (Laravel + Inertia)
- Секреты `.env` не в системе контроля версий
- AI API keys хранятся в базе данных (доступ ограничен аутентифицированным admin)

### Планируемые

- Role-based access control (Phase 1)
- Field-level visibility by role
- Access audit logging
- Consent management module
- Privacy policy version tracking
- Data export for subject access requests
- Data deletion/anonymization workflows

## App Store и мобильная публикация

При публикации мобильных приложений (Phase 5):

- Требуется URL Privacy Policy (App Store, Google Play)
- App Privacy Details должны точно описывать собираемые данные
- Учёт особенностей детских приложений (требования типа COPPA, age gates, parental consent)
- Минимально необходимый сбор данных для функциональности приложения

## Примечание о конфиденциальности AI Settings

Установленный модуль AI Settings (`/ai-settings`) позволяет настраивать API keys внешних AI-провайдеров (OpenAI, Anthropic, Gemini).

- API keys чувствительны — никогда не раскрывать в логах или документации
- Если функции AI в будущем будут обрабатывать персональные данные, может потребоваться дополнительная DPIA (Data Protection Impact Assessment)
- Документировать, какие данные отправляются AI-провайдерам, перед включением production AI features

## Хранение данных

Сроки хранения должны быть определены совместно с владельцем академии:

- Student records: обычно период зачисления + законный срок хранения
- Financial records: согласно итальянскому бухгалтерскому/налоговому законодательству (часто 10 лет)
- Consent records: период обработки + период доказательства
- System logs: рекомендуется 90–365 дней

**Статус:** Политика хранения ещё не определена — требуется уточнение от клиента.

## Права субъектов данных (GDPR Articles 15–22)

Система в итоге должна поддерживать:

- Right of access (export student/parent data)
- Right to rectification (edit records)
- Right to erasure (with legal exceptions)
- Right to restriction of processing
- Right to data portability

**Статус:** Не реализовано — запланировано на более поздние фазы.

## Изменения, требующие обновления документа по конфиденциальности

Обновлять этот документ, когда:

- Новые модули собирают персональные данные или данные детей
- Изменяются права ролей
- Планируются или запускаются мобильные приложения
- Функции AI обрабатывают пользовательские данные
- Данные передаются третьим лицам
- Определяются политики хранения или удаления

## Контакт и ответственность

Ответственность за защиту данных лежит на **академии (Data Controller)**. Техническая поддержка реализации предоставляется командой разработки как **Data Processor**, когда это применимо.

Окончательные юридические тексты, формы согласия и политики конфиденциальности должны быть одобрены академией и квалифицированным юридическим консультантом перед использованием в production.
