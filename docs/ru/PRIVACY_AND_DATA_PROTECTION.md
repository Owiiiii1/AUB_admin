# AUB — Конфиденциальность и защита данных

> Технические заметки проекта, **не** юридический текст. Перед App Store и публичными политиками нужна юридическая экспертиза.

AUB обрабатывает **персональные данные** и **данные детей**. Интерфейсы: web-админка, workplaces персонала, будущий Flutter (`AUB_app`) через HTTPS API (API ещё нет).

## RBAC как требование конфиденциальности

RBAC нужен для минимизации данных. **Web-RBAC существует.** Field-level правила и авторизация Flutter API **нет**.

- Персонал должен видеть только нужное для работы — **намерение**, не полностью enforced
- Преподаватели не должны видеть платежи и контакты родителей без разрешения — **не реализовано**
- Доступ родителя/студента во Flutter — только свои данные — **API ещё нет**

## Типы данных

| Категория | Примеры | Чувствительность |
|-----------|---------|------------------|
| Персонал | Имена, email пользователей/преподавателей | Персональные |
| Студенты | Имена, даты рождения, адреса в `customers` | **Данные детей** |
| Родители | Встроенные поля отца/матери | Персональные |
| Рядом со здоровьем | Срок медсправки, сканы документов | Может быть **special category** |
| Геолокация (будущее) | Teacher check-in lat/lng/accuracy/timestamp | Персональные; сейчас не собираются |
| Ключи ИИ | `ai_provider_settings.api_key` | Секреты (encrypted в Laravel) |
| Логи | IP, user agent в `activity_logs` | Ограниченные персональные |

Записи согласий — **planned**: целевые `ConsentType`, `ConsentDocumentVersion`, `ConsentRecord`. Возможные types: privacy; data processing; photo/video; marketing; special activity. Не реализовано.

## Данные детей

Цифровые каналы (web + будущий Flutter) должны фиксировать согласие там, где это требуется политикой академии и применимым законодательством. Для несовершеннолетнего согласие связывается с parent/guardian **где это требуется**. Конкретный возрастной порог **не хардкодить** в domain model до legal / compliance review. **Не реализовано.**

Файлы студентов лежат на диске Laravel **public** (`students/{id}/documents`). Это **разрыв privacy** (URL могут быть доступны при живом symlink). Не описывать как private storage.

## Принципы GDPR vs факт

| Принцип | Факт |
|---------|------|
| Прозрачность | Публичной Privacy Policy ещё нет |
| Минимизация | RBAC есть; field-level visibility **нет** |
| Точность | Редактирование есть; view-audit **нет** |
| Срок хранения | Политика не определена |
| Целостность | HTTPS, хеш паролей, CSRF в web |

## Технические меры

### Реализовано

- HTTPS (`https://aub.owlsolutions.net`)
- Session authentication (web)
- Хеширование паролей
- CSRF (Laravel + Inertia)
- `.env` не в git
- Encrypted AI API keys в БД
- Доступ к **меню/маршрутам** по ролям (`role.*`)
- `can_write` / `can_delete`
- CRUD activity logging (`ActivityLogger`) — не полный access/view audit

### Security Foundation (обязательно до широкого mobile rollout — не реализовано)

Поднять из «будущих улучшений» в **обязательный foundation**:

- Private storage документов детей
- Field-level ACL
- Scoped-доступ преподавателя (только назначенные дети/группы)
- Access/view audit чувствительных данных
- Матрица API-авторизации
- Безопасность мобильных токенов
- **2FA для административного персонала**
- Записи согласий / privacy (`ConsentType` / `ConsentDocumentVersion` / `ConsentRecord`; возрастной порог не хардкодить)

Плюс (по-прежнему нужно): выгрузка / удаление по запросу субъекта.

Не писать, что RBAC или «логирование доступа» только planned, если читатель решит, что ничего нет: RBAC и CRUD-логи **есть**, но они неполные.
