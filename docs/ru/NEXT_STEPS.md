## Рекомендуемые следующие шаги (по приоритету)

### 1. Учёт посещаемости (Фаза 3)

- Отметка присутствия по занятию / группе
- Интеграция с workplace преподавателя
- Зависит от: недельное расписание + группы курсов (готово)

### 2. Workflow зачислений (завершение Фазы 2)

- Статусы (active, withdrawn, completed)
- Перевод между группами с историей
- Решение: оставить `customers` или мигрировать на отдельную таблицу `students`

### 3. Родители как отдельная сущность (Фаза 2)

- Таблица `parents` + pivot `student_parent`
- Замена встроенных полей отца/матери когда будет готово
- Будущее: mobile-доступ для родителей

### 4. Модуль документов (Фаза 3)

- Отдельная страница `/documents` (сейчас заглушка)
- Централизованный список документов, типы, правила хранения
- Переиспользовать пути загрузки из профиля студента

### 5. Модуль коммуникаций (Фаза 3)

- Заглушка `/communication` → сообщения/уведомления
- Иконка сообщения в списке студентов (сейчас не работает)

### 6. Связь Teacher ↔ user (Фаза 2)

- `teachers.user_id` для входа преподавателя
- Ограничение видимости полей профиля студента по ролям
